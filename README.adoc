= M2 ROM & Data-Driven ROM

A 28-hour cours intégré on numerical methods useful for digital twins, with mandatory data assimilation and practical Python notebooks.
The repository also hosts a broader, reusable ROM reference library.

* https://feelpp.github.io/course-rom/[Course website]
* `docs/`: the M2 course component, session routes, practicals and teaching archive.
* `materials/`: the broader reference component, starting with the digital-twin introduction.
* `teaching/instructors/`: instructor preparation outside the published site.

== Build the course website

Use Node.js 22 or newer and Python 3.12 or newer.

[source,bash]
----
npm ci
python3 -m venv .venv-course
source .venv-course/bin/activate
python -m pip install -r requirements-course.txt
npm run antora
npm run verify:labs
python scripts/verify-course-site.py
npm start
----

Open the local address printed by `npm start`.
The course and library retain separate navigation under one site.
For a different interpreter, set `COURSE_PYTHON` when invoking the build.

For prose/navigation editing without a numerical environment, run `npm run site:static`.
It writes a clearly labeled, unexecuted preview to `build/static-site/` and leaves `public/` intact.
See link:CONTRIBUTING.adoc[Authoring and verification] for conventions, source inventory and notebook release checks.

== Executable pages and notebook downloads

The first three practicals are authored in `docs/modules/ROOT/pages/labs/`.
Sessions 2–3 now include native Galerkin/POD and certification notes, executable practicals, and follow-up homework.
The Feel++ Antora Jupyter extension converts the pages selected in `site.yml` to notebooks using `asciidoctor-jupyter`, and generates a source-hash manifest.
Antora then executes opted-in Python blocks using the Feel++ AsciiDoc extension and publishes their results, including Matplotlib figures.
The Feel++ UI supplies the notebook download and print controls.

Notebook attachments and their provenance manifest are generated in the Antora content catalog. Edit the source page, not an exported notebook. The downloadable requirements file is copied from the root requirements file.
Student notebooks contain runnable starter code and activities. Instructor verification artifacts are written under ignored `build/course-release/`.
Historical pages are not automatically executed or exported: they require separate review before joining the release list.

`npm run validate` fails on Antora errors, including unresolved cross-references.
The documentation CI job runs separately from the legacy Feel++ C++ and container jobs, and publication follows successful documentation checks on `master`.

== Renaming the project

By default the project is named  `course-rom` if you cloned the repository `feelpp/course-rom`.
However if you used the previous repository as a template, then the project is renamed using the name of the repository using the script `rename.sh` at the initialization of the repository.
If the name does not suit you, you can change it again using the script `rename.sh` and providing the new name as argument.

WARNING: the script `rename.sh` will rename the project however some url might be set properly if you rename the project yourself. You need to check the following files: `docs/site.yml` and `docs/package.json` and fix the urls after the rename process is done.

== Updating the {project} version

The version of the project is defined in the files `CMakeLists.txt`, `docs/antora.yml` and `docs/package.json`. 
You need to update with the same version in all files.
